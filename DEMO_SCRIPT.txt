Hello everyone! Over 430 million people worldwide live with disabling hearing loss. Yet, most communication tools treat sign language translation as mere word-for-word substitution, completely missing ASL syntax rules, handshape parameters, and accessibility display requirements. Today, I am excited to present SignBridge Agent, an intelligent multi-agent accessibility assistant designed to solve this exact problem.

[0:20 - WHAT IT IS]
SignBridge Agent is built using Google's Agent Development Kit (ADK 2.0). Under the Agents for Good track, it bridges the gap between spoken English and American Sign Language gloss, providing real-time syntax checking, handshape breakdowns, and specialized display device formatting.

As you can see on screen, SignBridge Agent brings together three core pillars: an ADK Multi-Agent Architecture, a Model Context Protocol server, and automated security governance.

[1:00 - ARCHITECTURE]
(show assets/architecture_diagram.png)
Let's take a look at how data flows through the agent system. When a user submits a query, it first enters our Security Checkpoint node. This node scrubs sensitive personal information like phone numbers and emails, and checks for prompt injection attempts. Once verified, the request passes to our root orchestrator agent. The orchestrator delegates specialized tasks to sub-agents: translator_agent handles ASL gloss conversion and syntax checking, while accessibility_agent formats outputs for high-contrast or tactical display devices. Both agents leverage our custom MCP server for dictionary lookups and syntax validation.
